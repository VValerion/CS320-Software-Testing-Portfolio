## Reflection

### Ensuring Code Is Functional and Secure
I ensure that my code is functional and secure by validating behavior through automated unit testing and enforcing constraints at the service level. Writing tests alongside implementation helps catch defects early and confirms that changes do not introduce regressions. Clear validation rules and exception handling further reduce the risk of incorrect or unstable behavior.

### Interpreting User Needs
User needs are interpreted by translating requirements into precise and testable rules. In the contact service project, requirements such as unique identifiers, required fields, and update restrictions were directly implemented in the service logic and verified through unit tests. This approach ensures the software behaves exactly as specified and avoids ambiguity.

### Approach to Software Design
My approach to software design is incremental and structured. I begin by defining clear responsibilities for each class and keeping designs focused on a single purpose. Functionality is implemented in small steps and verified through testing before moving forward. This method improves readability, simplifies debugging, and supports long term maintainability.
